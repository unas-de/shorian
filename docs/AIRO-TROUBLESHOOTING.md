# تشخيص تسجيل الدخول في معاينة Airo

المشكلة المبلغ عنها 31 أكتوبر 2026 تضم تحذير hydration على خاصية `data-scribe-recorder-ready` ورسالة رفض دخول. الخاصية ليست ضمن كود التطبيق، وترجح حقن إضافة Scribe قبل React. حُصر suppressHydrationWarning في عنصر html فقط، دون تعطيل فحص بقية الواجهة. تعطيل الإضافة أو فتح نافذة خاصة دون إضافات يساعد على التحقق من المصدر.

رفض الدخول كان يُعرض برسالة صلاحيات واحدة رغم وجود حالتين منفصلتين: عدم تطابق Origin مع Host داخلي غيّره proxy، أو غياب DEMO_MODE=true. لا يجوز حل ذلك بإزالة فحص المصدر أو تجاوز عضوية العيادة.

## إعداد الاستضافة المطلوب

في متغيرات بيئة Airo/الخادم، اضبط:

```
APP_ORIGIN=https://id6i6dm2od.preview.c35.airoapp.ai
SESSION_SECURE=true
```

APP_ORIGIN هو الـorigin الدقيق فقط: دون `/` مسار أو `?airoShareToken` أو كلمات مرور. عند تغير رابط المعاينة/النطاق النهائي حدّثه وأعد تشغيل التطبيق. المتغير على الخادم وليس NEXT_PUBLIC. لا تُنسخ روابط المشاركة أو رموزها إلى Git أو env.

لتشغيل **البيانات الاصطناعية التجريبية فقط** يمكن إضافة `DEMO_MODE=true`. هذا يتيح حسابات العرض لمن يفتح المعاينة، فلا يُفعّل في قاعدة فيها معلومات خاصة أو مرضى حقيقيون. عند DEMO_MODE=false تختفي علامة تبويب التجربة ويبقى الدخول بحساب حقيقي أو إنشاء عيادة. إنشاء حساب جديد لا يثبت ملكية البريد بعد؛ راجع حدود الإصدار.

اسحب الإصلاحات ثم أعد البناء/النشر وأعد تحميل الصفحة. زر الدخول التجريبي لا يظهر إلا بعد استجابة `/api/auth/config` بـ`demoEnabled:true`. `/api/auth/config` لا يكشف مفاتيح أو عضويات، واستجابته بدون cache.

## الفروق في الاستجابات

- `REQUEST_ORIGIN_REJECTED` مع 403: إعداد رابط الاستضافة غير متطابق؛ صحّح APP_ORIGIN، ولا تعطل حماية CSRF.
- `DEMO_DISABLED` مع 403: وضع العرض غير مفعّل، وليس نقصًا في عضوية دور طبي.
- `INVALID_CREDENTIALS` مع 401: البريد/كلمة المرور غير صحيحة.
- `UNAUTHENTICATED` مع 401 بعد نجاح الدخول: افحص استمرار Cookie/HTTPS وسياق iframe، مع إخفاء قيم الجلسة في أي لقطة أو تقرير.
- رد HTML من بوابة Airo بدل JSON التطبيق: تحقق من صلاحية المعاينة/المشاركة لدى Airo؛ لا تعدّل أدوار العيادة لحل صلاحية بوابة الاستضافة.

لا يتم الوثوق بـX-Forwarded-Host المرسل وحده. عند ضبط APP_ORIGIN تُقبل مطابقة نفس الأصل المصرح به فقط؛ المصادر الخارجية تظل مرفوضة. دون المتغير يستمر فحص Host الأصلي.

## التحقق

`npm test` يشمل حالات مصدر عادي، proxy داخلي، مصدر مهاجم، x-forwarded-host مزيف، Origin غير صالح وإعداد خاطئ. اختبار `scripts/login-proxy-check.mjs` يُشغّل في نسخة build معزولة: يحقن سمة Scribe قبل hydration، ويسجل الدخول عبر proxy يغيّر Host، ويتحقق من الجلسة بعد تحديث الصفحة ورفض المصدر الخارجي وإخفاء/رفض Demo عند تعطيله.

لم يُتحقق من النسخة المنشورة على Airo مباشرة: اتصال بيئة العمل بنطاق المعاينة رفضه وكيل الشبكة قبل الوصول إلى الموقع. لا تعني هذه الملاحظة أن موقع المستخدم نفسه أعاد 403.
