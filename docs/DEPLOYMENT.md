# نشر شُريان على الإنترنت

## الحالة

ملفات النشر جاهزة؛ **لم يُنشأ خادم خارجي ولم يصدر رابط عام**. يلزم حساب استضافة وصلاحية نشر. لا ترسل كلمات مرور أو مفاتيح في المحادثة. نشر بيئة Codex يحفظ بيئة التطوير ولا ينشر الموقع للعامة.

## GoDaddy

اختار المستخدم GoDaddy، والخطة الحالية Web Hosting/cPanel مشتركة. لم يُنفذ نشر عليها؛ يلزم التأكد من دعم Node.js دائم أو الانتقال إلى VPS. إعداد VPS والخطوات في [GODADDY.md](GODADDY.md). لا ترفع ملفات Next.js إلى public_html باعتبارها موقعًا ثابتًا.

## خيار بديل مجهز: Render

`render.yaml` يعرّف خدمة Node واحدة مع قرص دائم للمجلد `.data` كاملًا (PostgreSQL والمرفقات ومفتاح توقيع روابطها). اختيرت خطة `standard` لتوفير هامش ذاكرة لNext.js وPostgreSQL داخل العملية؛ الخادم المحلي استهلك نحو 417 MiB قبل أي اختبار أحمال. الخدمة والقرص مدفوعان: راجع السعر المعروض من Render قبل الإنشاء. لا توجد موارد أو رسوم أُنشئت من مجرد وجود الملف.

1. ارفع ملفات المشروع، بما فيها lockfile وmigrations وscripts، إلى مستودع GitHub الذي ستربطه. **لا ترفع** `.env.local` أو `.data` أو كلمات المرور أو `node_modules` أو `.next`.
2. من حساب Render اختر إنشاء Blueprint واربط المستودع. راجع إعدادات `render.yaml` والخطة والقرص ثم أنشئ الخدمة.
3. ينفذ البناء `npm ci --include=dev --no-audit --no-fund && npm run build`. الاحتفاظ بـdev dependencies متعمد لأن تهيئة DB تستخدم tsx.
4. التشغيل `node scripts/deploy-start.mjs`: يرحّل القاعدة ويهيئ البيانات الاصطناعية عند تفعيل Demo داخل عملية قصيرة، ثم يغلقها قبل تشغيل Next. لا تشغّل pre-deploy migration على القرص نفسه من عملية متزامنة.
5. ينتظر Render نجاح `/api/health` (استعلام حقيقي في القاعدة). خذ رابط HTTPS من لوحة Render، واختبر تسجيل الدخول والحفظ والمرفقات وإعادة التشغيل.
6. اختبر إنشاء مريض اصطناعي ثم إعادة تشغيل الخدمة واسترجاعه. توقف الخدمة مؤقتًا عند النسخ الاحتياطي؛ لا تفتح نسختين من PGlite على القرص نفسه.

الإعدادات المجهزة: HTTPS cookies عبر `SESSION_SECURE=true`، وقاعدة `.data/postgres`، و`DEMO_MODE=true`. حسابات العرض عامة لكل من يفتح الرابط عند تفعيل Demo، بما فيها مدير المنصة الاصطناعي؛ لا تضع معلومات خاصة فيها. بيانات بيئة التطوير الحالية **لا تُنسخ** إلى الاستضافة؛ يهيئ seed بيانات اصطناعية جديدة عند أول تشغيل.

Render يوفر اسم نطاق فرعي للخدمة؛ النطاق المخصص اختياري ويمكن ربطه لاحقًا. لا تدّعي رابطًا أو نجاح نشر قبل استجابة HTTPS وفحص الرحلة عليه.

## خادم VPS بديل

يتطلب Node 24 ومجلد تطبيق دائم وذاكرة كافية وHTTPS reverse proxy وخدمة process manager. شغّل خادمًا واحدًا فقط من مجلد المشروع باستخدام `node scripts/deploy-start.mjs` مع `PORT` و`SESSION_SECURE=true`، واضبط الوكيل ليحافظ على Host الخارجي (فحص CSRF يعتمد عليه). احفظ `.data` كاملًا خارج أي تنظيف تلقائي للإصدارات.

## حدود الإطلاق

الإعداد الحالي لنشر **تجربة اصطناعية** على الإنترنت. قبل تشغيل عيادات حقيقية أكمل قائمة `VALIDATION.md`، وعطّل دخول Demo، واربط التحقق من البريد/استعادته، واختبر عزل وصلاحيات ونسخ/استعادة PostgreSQL/التخزين الإنتاجيين. الاستضافة Serverless ذات القرص المؤقت (ومنها نشر النسخة الحالية مباشرة على Vercel) لا تحفظ بيانات PGlite والمرفقات على نحو مناسب.
