# البنية والصلاحيات

## خريطة الملفات

- `app/page.tsx`: مساحة العيادة، تسجيل الدخول، وواجهة منصة منفصلة حسب الجلسة.
- `app/globals.css`: Design Tokens، Cairo محلي، RTL/LTR، استجابة الشاشات، CSS الطباعة.
- `app/api/[...path]/route.ts`: أوامر الأعمال، التحقق بالـZod، الصلاحيات والمعاملات.
- `app/api/files/[id]/route.ts`: بث ملفات خاصة والتحقق من الروابط المؤقتة.
- `lib/db.ts`: PostgreSQL محلي دائم، migrations، قفل العملية، seed وscoped transactions.
- `lib/auth.ts`: جلسات وأدوار من العضويات الفعلية؛ لا ثقة بالدور المرسل من المتصفح.
- `lib/storage.ts`, `lib/backup.ts`, `lib/adapters.ts`: روابط خاصة ونسخ/استعادة وعقود المزودين.
- `migrations/001_core.sql`: الجداول الأساسية والفهارس والعلاقات وRLS والأدوار.
- `migrations/002_integrity.sql`: حدود الباقات وقيود الدفع والاسترداد.
- `migrations/003_cash.sql`: الورديات والخصومات وقيود مواعيد العمل.
- `tests/database.test.ts`, `scripts/http-check.mjs`, `scripts/browser-check.mjs`: تحقق قاعدة وخادم ومتصفح.

عضوية الحساب متعددة العيادات مدعومة في المخطط والخادم ومبدل يظهر عند وجود عدة عضويات؛ seed لا يمنح حساب عيادة عضوية في الأخرى. إنشاء/إدارة هذه العضويات عبر دعوات آمنة ما زال متبقيًا. وصول الدعم الطبي الاستثنائي غير متاح؛ المنصة مرفوضة من APIs المرضى، ولا توجد واجهة تمنحها وصولًا طبيًا.

RLS المالية تمنع الطبيب من دفاتر الأموال، وRLS الطبية تمنع غير الطبي من النصوص والمرفقات. يقيّد الخادم الوظائف التفصيلية (الاسترداد والإعدادات مثلًا). وصول nurse مسجل كدور في المخطط؛ لا توجد رحلة تمريض كاملة جاهزة، فلا يُستخدم قبل إكمال سياسات العلامات الحيوية وواجهتها.

## حالات الأعمال

- الموعد: booked → confirmed/arrived/cancelled/no_show؛ arrived → in_progress عبر بدء زيارة الطبيب؛ اعتماد الزيارة → completed. إلغاء/نقل لا يعدّل طبيًا أو يمحو فاتورة أو دفعة.
- الزيارة: draft مع optimistic version → signed مع طبيب وتاريخ؛ trigger يمنع تعديل/حذف السجل المعتمد. التصحيح صف append-only في clinical_notes.
- المال: فاتورة وبنود مستقلة؛ مجموع المقبوضات − المسترد يحدد المدفوع الصافي والمتبقي. لا يُسمى إصدار الفواتير تحصيلًا؛ صافي الحركة النقدية ليس ربحًا محاسبيًا.
- التجربة: 14 يومًا؛ trial/active/manual_active تسمح بالكتابة، وexpired/cancelled/انتهاء trial تجعل القراءة والتصدير والطباعة متاحة. لا حذف بيانات عند تغيير باقة. حد الأطباء والمستخدمين داخل معاملات وTriggers؛ التخزين حد محلي ثابت مؤقت.

## حدود التصميم

PGlite ينفّذ المعاملات بتسلسل داخل العملية. Trigger الحجز يستخدم advisory lock ونطاق تداخل زمني. هذا يثبت المنع في التنفيذ الحالي؛ نقل النظام إلى PostgreSQL متعدد العمليات يحتاج exclusion constraint مناسبة أو عزل/قفل وإعادة محاولة مثبتة باختبار اتصالين مستقلين. لا تدّعي اختبارات PGlite إثبات أحمال نشر موزع.

المدير لا يصل للمحتوى الطبي افتراضيًا؛ `medical_access` موجود كصلاحية صريحة لكن منحها ليس زرًا عامًا في الواجهة. لا يوجد SQL endpoint، ولا يمكن للمستخدم تعديل سياق RLS بنفسه عبر API. مالك الاتصال الداخلي هو دور migration موثوق؛ لا تُستخدم صلاحياته مباشرة في عمليات العيادة.
